HIVE.
Product Lab.

Active 2026~46 agentsProduction-company structure

HIVE is a lab that mimics a production company. About 46 agents play roles across engineering, product, design, legal, strategy, and ops, and ship a real downloadable product through formal alpha gates. The Director does not do the work; it routes, reviews, and writes the post-cycle directive.

STRUCTURE

A production company, not a hierarchy

The premise is to run an autonomous lab the way a small product company actually runs, not the way an idealized org chart says it should. Engineering writes code. Product owns scope. Design owns surface. Legal flags compliance early. Strategy reads the market. Ops keeps the cycle infrastructure honest. The Director does not pre-assign work to layers; it pulls in whoever has perspective on the decision in front of it, the same way a real company would.

The org chart is the conceptual structure. Execution is flat. The Director launches any agent directly, no intermediate layers.

Memory is three layers of markdown. Long-term holds the ratified rules. Cycle holds what is happening this run. Conversation holds what the agent is currently thinking, and gets wiped between turns. The wipe is deliberate. It stops one specialist's working hypothesis from polluting the next decision.

The Director changes how the lab works, not what it builds. Trust the loops; intervene only when they fail.

Operating principle

PRODUCT

What's being built

The product the lab is shipping is a downloadable privacy-first tool for collective intelligence through distributed local AI. Free for personal use. No accounts, no servers holding user data, no telemetry. Local extraction model on each device, classical reasoning engine over structured rules, peer-to-peer rule distribution. Cross-platform with a shared Rust core via FFI.

The lab ships through formal alpha gates with build-engineer attestations, signed verification artifacts, and a streak-and-verdict mechanism that tracks sustained sequences of clean cycles. Around 1,688 passing tests at gate as of last count, zero failures.

VERIFICATION

Why byte-identical builds matter

Dozens of consecutive cycles, same source in, same binary out, byte for byte. That sounds like nothing happened. It actually means something specific: no specialist agent introduced an undeclared change to the build output over that stretch. Anything that should have shown up would have shown up as a hash mismatch.

The point isn't the bytes. It's that drift in the build is now legible from outside the lab. Without that, every "build still passes" claim is just another self-reported number.

SELF-CORRECTION

How the lab corrects itself

Between cycles the Director writes a directive about what to change going forward. The rule for what counts as a directive is strict. Process changes, constraint changes, gate changes are allowed. Specific decisions about what to build next are not.

"Do this thing next cycle" is the wrong shape because it crowds out the lab's own judgment, which is the whole point of running it autonomously. "When condition Y holds, the verification gate must include external review before merge" is the right shape. It tightens the structure without prescribing the move; the lab still decides what to actually do, just within a tighter shape.

The interesting failure mode is when the Director starts smuggling specific decisions into process changes. That's what the post-cycle review process is for: catch the smuggle before it ratifies.
